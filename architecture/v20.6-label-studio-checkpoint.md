# V20.6 — Label Studio refinement

Builds on V20.5 and existing Take App parity and simplicity requirements. No new pages or dependencies in prototype.

- Existing 40 × 25, 50 × 30 and 60 × 40 mm presets retained. Select nominal 203 or 300 DPI. Compute integer nominal printer dots per QR module including four-module quiet zone on each side; minimum four dots/module for selected print job. Preserve original payload and QR SVG. Browser/driver may rescale or rasterize differently; this is not a printer calibration or ISO quality grade.
- Compact black/white printed layout prioritizes QR, product/device name and optional SKU/serial/repair reference. Long text can be shortened; long opaque tokens show an explicitly labeled eight-character tail for visual checking only, not a unique lookup key. Full encoded identifier is visible in preview. No customer personal data added.
- Explicit A4 sheet pagination and thermal page dimensions. Keep 250-label job limit and existing purchase scope/version/role checks. Printing never changes stock, purchase or receipt records. Print guidance requests matching paper size and DPI, actual size, disabled headers/footers and one physically scanned test label before a batch. No print-success assertion or physical printer integration.
- Preview and print use the same label card; job validation rejects missing records, invalid copy counts and undersized nominal QR modules.
