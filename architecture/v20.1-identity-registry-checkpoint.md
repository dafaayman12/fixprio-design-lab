# V20.1 — Identity registry prototype checkpoint
2026-11-26. Builds on [stock safeguards](v20.1-stock-safeguards.md) and [approved design direction](v20.1-permanent-qr-identity.md).

## Implemented
- Migrate the existing browser-local registry document from version 1 to 2 at the same storage key, preserving existing product tokens and adding validated repair token/reference mappings and the existing serial fixture identity.
- New repair identifiers use cryptographic random 128-bit tokens; the persisted reference sequence prevents reuse after a fresh runtime. Persist the identity before creating the synthetic booking.
- Repair domain state remains session-only. If an issued repair token is recognized but the booking is unavailable, the scanner explicitly explains this; it must not offer an action on another repair or issue a replacement automatically.
- Product renames and SKU edits do not change printed product tokens. Reject new SKU conflicts across products/variants and reserved Fixprio/repair/demo serial namespaces. Resolve ambiguous aliases fail-closed rather than selecting the first match.
- Validate registry integrity and fail closed on malformed data or detected stale storage. Keep existing UI and stock command restrictions; no new screens.

## Remaining boundaries
This is browser-local scaffolding, not the permanent server identity authority. Variant tokens, external barcode association, revocation, individually tracked unit activation/receipt/sale, durable repair records and cross-device persistence remain unimplemented. The serial identity is a validated fixed demo fixture, not general issuance. Old previously issued session-only repair labels cannot be recovered from V1 storage. Simultaneous tab writes can race; no concurrency guarantee. Full production authorization and transaction/recovery remain required. No live data, production repo or deployment changed. This commit saves documentation only; full historical source archive transfer remains unverified.
