# V20.2 — Incoming product registration
2026-11-26. Extends [V20.1 registry](v20.1-identity-registry-checkpoint.md) and preserves [Take App parity](../specifications/take-app-parity.md).

- Scanner lookup recognizes valid check-digit GTIN-8, UPC-A, EAN-13 and GTIN-14 numeric inputs. Canonical 14-digit aliases preserve leading zero semantics. No external product lookup. Unknown Fixprio tokens, malformed GTINs, URLs and ambiguous matches never offer registration.
- Owner demo role may create an unpublished zero-stock product using the existing editor or explicitly associate the code with an eligible existing product. Save & labels opens existing Label Studio, clears previous selection and filters to the selected product's SKU. Repeated or conflicting barcode association is rejected; catalog edits cannot steal registered aliases. Existing QR tokens remain unchanged. Generic variant and serialized associations are deliberately unavailable.
- Barcode alias is optional catalog metadata in the existing version-2 browser-local registry. No new staff page or database. Existing role policy reused: catalog saves and barcode registration require stockAdjust (Owner); staff permissions subject to review.
- Purchase order workflow can select the registered product and receive by either manufacturer barcode or Fixprio QR. No stock mutation from registration or print preparation. No automatic purchase-line insertion; use existing purchase editor. No purchase-order bulk label preparation yet (next milestone).
